# 深入优化清单：0.14.0

复查日期：2026-09-29。依据为当前源码、内存模拟验证、GitHub 检查结果与社区审核页面。以下是待实施方案，当前版本未修复这些新发现的问题；真实 AI 分类准确率和 Obsidian 实机表现仍需单独验证。

发布已完成：[GitHub 0.14.0](https://github.com/clarkdonaldtfgbw5081-del/current-note-chat/releases/tag/0.14.0)公开；[插件市场页面](https://community.obsidian.md/plugins/current-note-chat)提供安装入口，0.14.0 自动检查为 Completed。发布检查通过与产品体验可以继续改善是两件独立的事。

## 1. 保存与归档需要形成完整流程

普通问答的 `finally` 等待保存，但没有检查返回的笔记路径；保存函数捕获异常后返回 null，之后仍可启动分类。费曼学习完成时也有类似顺序。模拟存储失败后观察到分类被调用，不能把“完整对话保存成功”当成现有的硬性前提。

对应代码：[普通问答](../src/ui/widget.js#L270)、[保存函数](../src/main.js#L236)、[费曼完成](../src/ui/feynman.js#L165)。

建议：只有完整对话保存成功后才启动自动归档。把等待中的任务和必要上下文持久化，重启后继续未完成任务；对网络限流和临时写入失败采用有上限的重试。用户关闭归档或取消时必须保留取消状态，避免恢复已取消任务。分别显示“回答完成”“对话保存失败”“知识归档失败”，并提供明确的恢复入口。

验收：模拟磁盘写入失败时不启动分类；恢复后只有一次归档；关闭或重启发生在每个写入阶段时，结果可恢复且不会覆盖手写内容。

## 2. 归档身份不能依赖来源文件路径

归档 ID 由来源 key 和用户消息 ID 组成。来源改名会改变 key，原来的去重记录便匹配不到。模拟同一条问题及回答在改名前后归档，目标笔记出现两个相同段落。现有 rename 逻辑更新的是归档目标路径，没有迁移来源身份。

此外，费曼完成后的自动归档使用最后一条作答消息 ID，手动归档使用 `lesson:topic:revision`，同一份报告存在重复追加的风险。后者已确认 ID 不同，尚未用真实模型跑完整双入口流程。

对应代码：[ID 与去重](../src/knowledge-notes.js#L75)、[rename](../src/knowledge-notes.js#L58)、[手动费曼归档](../src/main.js#L249)、[自动费曼归档](../src/ui/feynman.js#L166)。

建议：使用独立于路径的会话 ID、轮次 ID 和学习报告 ID，统一自动与手动入口。把归档状态放在插件元数据中，不向笔记正文重新加入用户此前要求删除的内部标记。提供更改归类、撤销本次追加与版本记录；明确去重记录的保留策略，处理当前 400 条上限后的旧回答。

验收：文件改名、文件夹移动、重启、网络重试、自动后手动归档均只产生一份对应内容；迁移不丢失原来的绑定。

## 3. 分类从名称匹配升级为受限的主题检索

当前只用问题中的英文词和中文相邻字匹配路径，取前 120 个候选；候选只有名称与路径，模型没有读它们的正文。像“解释这题”这样的泛化问题缺少主题信息。模拟 131 篇笔记时，实际相关笔记未进入候选集。这个验证说明候选召回有缺口，不能据此推算真实分类准确率。

对应代码：[候选检索](../src/knowledge-notes.js#L22)、[请求输入](../src/knowledge-notes.js#L27)。

建议：结合问题和回答提取关键词，建立知识目录内的标题、别名与简短摘要索引，加入中英文同义词。通过固定分类表与目录别名约束目录命名；已有目录优先，减少“概率论”“概率统计”等碎片。语义检索可以后续加入，但应明确索引范围、数据发送范围与费用。

当前本地调用 `getMarkdownFiles()` 后过滤知识目录，目录外路径不会发送给分类模型；社区检查因此新增 Vault Enumeration 提示。可改成从知识目录节点向下遍历，只枚举该目录，兼顾隐私边界和大仓库性能。0.8 是模型返回的自评阈值，尚未校准成真实正确率。

验收：建立至少 100 条人工标注问题，覆盖泛化问句、同义词、双语、跨主题与同名笔记，报告候选召回率、错误合并率和待整理比例；优先降低错误合并。确认不会读取或发送目录外候选数据。

## 4. 知识笔记应从追加记录发展为可复习的内容

当前“归入同主题”实际上追加一段摘要，不会比较已有正文，因而同一概念可能反复出现。新建笔记还有 H1 与首个 H2 同名的问题，说明图保留了这一现状。

对应代码：[段落模板与追加](../src/knowledge-notes.js#L112)，效果见[说明图](SCREENSHOTS.zh-CN.md#3-生成的知识笔记)。

建议：采用“核心结论 → 成立条件 → 公式与例子 → 常见误区 → 复习问题 → 来源”的可选模板。将本次新增内容与已有概念做语义比较，已存在的内容只补充来源；矛盾内容标记为待核对。先展示合并预览，支持撤销，保护用户手写部分。避免 AI 在资料没有依据时补写条件或断言。

较长回答目前只向分类请求提供前 24000 字符；可按结构分段提炼，再去重合并，注明覆盖范围并设置费用上限。公式、代码块、表格、Callout 和引用需要专门的导出样例，标题无需在新笔记中重复。

验收：同一知识点连续问五次仍是一篇结构清晰的笔记；新条件与来源不会丢失，旧手写内容原样保留；重复内容不会仅因措辞变化再追加。

## 5. 费曼学习加入长期证据与错误诊断

当前已有解释、应用、再次讲解三个阶段以及作答证据校验，比单纯生成答案更适合检验理解。但评价仍依赖同一个模型，单轮通过不能说明几天后还会用。

建议：为常见概念增加典型误区与反例题，应用题按难度递进；对可计算的数学题加入独立结果检查。记录具体误区和资料依据，让反馈指向“哪里错、为什么、怎样改”。提供用户可配置的间隔复习，建议 1、3、7、14 天，并区分查资料练习与脱离资料复述。此处是未来产品建议，本次没有创建提醒或自动任务。

验收：只说“懂了”、复述提示或照搬原文不能通过；错误解法即使表述流畅也不通过；统计延迟复习表现，用户可追踪薄弱点是否真正改善。

## 6. 费用、状态和界面性能

分类与问答使用同一服务配置，额外请求暂时没有独立模型、成本预算或用量视图。队列仅在内存中；分类异常回退到待整理后，用户缺少具体失败原因。归档状态改变会调用整体界面刷新，再渲染聊天 Markdown；长回答和公式下的耗时尚未量化。

对应代码：[状态刷新与队列](../src/knowledge-notes.js#L66)、[异常回退](../src/knowledge-notes.js#L103)、[面板刷新](../src/ui/widget.js#L102)。

建议：增加分类专用低成本模型选项、内容指纹缓存、每日用量预算与归档任务列表，显示排队、生成、待整理、失败和取消的不同状态。将归档状态条改为局部更新，长对话分段或按可见内容渲染。对服务商限流采用明确、有限的重试，不能重复发送不确定是否已完成的收费请求。

验收：重复内容不重复付费分类；预算达到后清楚提示并保留原对话；80 条含公式消息下比较刷新前后的耗时、滚动稳定性和内存，依据测量结果调整实现。

## 7. 实机、主题与发布说明

说明截图使用真实 widget 代码，但浏览器中的 Markdown 和主题是演示环境。现有 93 项测试与三平台 CI 不能替代真实 Obsidian 的系统权限、截图、公式和键盘交互测试。

建议：覆盖默认浅色、深色和常用主题；检查阅读视图、实时预览、行内与块公式、表格、长代码、多语言路径、窄窗口和键盘焦点。Windows 混合 DPI 多显示器、macOS 屏幕权限、Linux 桌面门户分别实测，再补充原生截图与短视频。

社区仍提示可选 Codex CLI 的本机文件与进程能力、复制按钮的剪贴板写入和 PDF.js 中的动态代码构造器；已有用途说明见[审核说明](COMMUNITY_REVIEW.md)。新增的目录枚举提示可通过限定目录遍历优化。Release 中额外 ZIP 和许可证属于手动安装、源码和声明材料，不会由 Obsidian 下载；可简化资产展示，但不应因此遗漏许可证。
