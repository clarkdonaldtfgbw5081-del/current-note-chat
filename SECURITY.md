# Security

Do not include API keys, actual screenshots, private notes or chat histories in public reports. For a suspected vulnerability, use the repository's GitHub **Security → Report a vulnerability** feature if enabled. Otherwise contact the maintainer privately before sharing exploitable details publicly.

The plugin sends the selected file excerpts, question, recent conversation and/or reviewed screenshot to the configured AI provider. Provider retention policies apply. SecretStorage references are stored in plugin settings; secret values are retrieved only when a request is built.

Screen capture targets a matching display ID and fails if the display cannot be identified. Screenshot previews are enabled by default. Screenshot retry snapshots exist only in memory, expire after ten minutes, are bounded, and are cleared when the plugin unloads. Codex needs a temporary PNG file; it is removed after the process exits. An OS or application crash can leave that temporary file behind.

Codex runs in an ephemeral read-only sandbox. By default it ignores the local user configuration while retaining the local login. Read-only does not mean filesystem read isolation; it restricts writes. Turning off configuration isolation enables local configured services and tools. The plugin never installs Codex or logs the user in automatically.

The Codex backend uses Node.js filesystem calls for executable discovery and temporary screenshot files, and child processes to launch the CLI and stop its process tree. CLI arguments are passed as an array without enabling a shell; prompts are sent through stdin. These operations remain visible to the community scanner. API-only requests do not launch Codex.

Clipboard access in the plugin's own code only writes an answer after the user clicks Copy. It does not read clipboard contents. The bundled PDF.js library contains Function constructors for feature detection, compatibility fallbacks and optional compilation. PDF parsing explicitly sets `isEvalSupported: false`, disabling compilation of PDF-generated functions. This does not remove those constructors from the bundled library or guarantee that every dependency feature probe avoids them. The plugin does not evaluate AI answers as JavaScript or shell commands.

Chat history is persisted locally through Obsidian plugin data storage. It is not encrypted. Vault sync or backups may copy these files. Auto-saved Q&A notes are regular vault notes. Clear a conversation with **New chat** and delete exported notes separately if needed. The original legacy `sessions.json` is preserved after migration; remove it manually if you intend to erase that backup too.

By default, each conversation automatically updates one local Markdown note starting with the first message. This includes learner answers, hints and incomplete-response labels, but excludes streaming fragments. **New chat** or **New topic** retains that note; erasing plugin history does not erase saved notes. Set **Automatic note saving** to Off if you do not want this additional local copy. Per-answer saving and folder selection are also available. Note paths and bounded turn fingerprints are stored in plugin data to restore the association and preserve handwritten changes to unchanged turns.

AI classification is enabled by default alongside automatic note saving and makes an additional request to the configured provider after a complete answer, or after a completed Feynman round. It sends the question, answer/report and up to 120 candidate Markdown titles/paths only from the configured knowledge folder and subfolders. Existing note bodies and extra screenshots are not sent by the classification code. The Codex backend retains the filesystem-read caveat above. Long answers are truncated to 24,000 characters for classification; full transcripts stay local. Disable classification independently in settings, or disable automatic saving to stop it.

Knowledge writes use the Obsidian vault API and validate destinations within that folder. Only that folder is traversed for candidates; aliases can influence local ranking but are not included in the classification request. Existing notes receive appended sections; handwritten content is not automatically rewritten. Uncertain results go to Inbox, and classification failures retain the original answer there. Model confidence and semantic grouping are not guarantees of correctness. Archive paths and bounded hashes are persisted in plugin data, never embedded as opaque markers in Markdown. Up to 400 archive bindings are retained for duplicate prevention; clearing history does not delete knowledge notes. Manual archiving can retry a failed classification and retains previous archived sections.

When **Append questions to the asked note** is enabled (default), a finished question is appended to the end of the asked Markdown note via the Obsidian vault API — file questions to the file being asked, screen questions to the Markdown note open when submitted or queued. The append adds a question callout, optionally followed by the answer, and a conversation-note link when a transcript exists; the note's frontmatter is never modified. Screenshot questions are saved as PNG attachments using Obsidian's attachment folder settings. Notes inside the AI Q&A and knowledge folders are never written; non-Markdown targets are skipped. Appended question IDs are stored in plugin data (bounded to the most recent 200) to deduplicate recent retries; crashes before plugin-data persistence or older evicted IDs can still cause duplicates. Disable Append questions to stop source writes and their screenshot attachments. Include the AI answer only controls answer inclusion. These controls are independent of conversation auto-save.

The local recovery journal stores up to 20 pending tasks, with bounded question/answer text, provenance, classification results and prepared write content. These are unencrypted plugin data and may be copied by sync/backups. Saving must succeed before automatic classification; interrupted requests with unknown results pause until explicit retry, which may incur another charge. Disabling classification/automatic saving or changing the knowledge folder cancels old tasks. The daily classification counter measures locally reserved requests, including failures and interruptions, rather than provider billing. A classification-specific model override applies only to the API backend. Undo removes only an unchanged, hash-verified addition at its recorded position; edited or shifted sections are preserved.

The explicit knowledge-consolidation command sends the selected/current knowledge-note text through the configured Q&A backend and shows a revision preview before the user applies it. This is separate from automatic titles-only classification. The plugin reads a chosen destination locally to protect concurrent edits and deduplicate identical summary text; that read is not automatically sent to classification.

Feynman learning saves topics, frozen file excerpts, gaps and accepted answer evidence in the same local plugin data. Learning screenshots are not persisted; subsequent turns resend the same approved image while the bounded cache remains available. **New topic** clears learning progress and its transcript for the current source; ordinary Q&A and exported notes remain separate. A pass represents model assessment of the submitted answers and should not be interpreted as a guarantee of mastery.

Local review plans retain up to 100 topic/source records, dates, gaps and delayed-pass counts. They do not copy screenshots or frozen excerpts, schedule background AI calls, or create OS notifications. Turning off plan recording preserves existing records; remove individual plans from the review panel to erase them. The numeric independence check is limited to fully specified probabilities and a supported source formula, and is not a general proof or factual-verification engine.

Streaming fetch requests are aborted on cancellation or timeout. Obsidian's non-streaming `requestUrl` does not expose transport cancellation: the plugin ignores late responses, but an upstream request may continue and incur charges. Stopping a Codex process likewise cannot undo a request already accepted by a provider. Interrupted answers are not automatically saved as successful notes.

Rendered answers use Obsidian Markdown rendering. External images or content referenced in generated Markdown can cause additional network requests when rendered. Review generated content before applying or sharing it.
